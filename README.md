# Cross-cluster Influenza Virus Prediction Projects

This repository contains three independent projects for **cross-cluster prediction of influenza virus properties**, each covering the complete workflow from baseline model benchmarking to feature selection and hyperparameter tuning:

1. **Host Prediction** – multi-class classification (Human / Avian / Swine)
2. **Receptor Binding Preference** – binary classification (α2-6 vs α2-3)
3. **Virulence Prediction** – binary classification (Virulent / Avirulent)

All projects share a **grouped data splitting strategy** (by `Cluster` or `Subtype`) to ensure that training/validation/test sets are independent at the group level, enabling objective evaluation of model generalization.

---

## Data Description

Each project uses its own data file (paths can be adjusted in the scripts):

| Project | Data File | Label Column | Group Column | Classes |
|---------|-----------|--------------|--------------|---------|
| Host Prediction | `../data/host_markers_with_cluster` | `Host_class` | `Cluster` | Human / Avian / Swine |
| Receptor Binding Preference | `../data/all_binding_marker_matrix_with_subtype.csv` | `label` | `Subtype` | α2-6 receptor (1) / α2-3 receptor (0) |
| Virulence Prediction | `../data/markers_with_cluster.csv` | `label` | `cluster` | Virulent / Avirulent |

Common data columns:
- Feature columns (numeric marker matrix)
- Label column (as above)
- Group column (`Cluster` or `Subtype`)
- Additional metadata columns such as `Strain`, `Subtype`, `Host`, `Isolate_Id`, `marker_count` (excluded from features).

---

## Common Workflow

All three projects follow the same general pipeline:

- **Grouped splitting**: Test sets are generated by selecting whole groups (`Cluster` or `Subtype`). Training and test sets never share the same group. Both sets must contain all classes, and the training set must contain at least 2 groups.
- **Candidate test sets**: 1000 candidates are generated. Final 10 independent test sets are selected with Jaccard overlap ≤ 0.8 between test groups.
- **Validation set**: Strictly controlled within a given ratio range of the training+validation set. Groups are added one by one; if adding a group would exceed the upper bound, it is skipped. If no valid split is found, the run is skipped.
- **Fixed random seed**: `np.random.seed(...)` and `random.seed(...)` are set at the beginning of each script for reproducibility.
- **No cross-validation**: A single validation split is used per run (except grid search in Script 5, which uses the validation set directly).
- **Metrics**: ACC, Precision, Recall, F1, MCC, AUROC, AUPRC.

## Scripts

### 1. `Extract_key.py` – Keyword-based Mutation Marker Extraction

**Purpose**: Extracts potential mutation/marker strings from PubMed article titles and abstracts using a set of regular-expression patterns, and writes the articles containing at least one marker to a CSV file.

**Input**:
- `../data/abs_pubmed_influenza_abstracts.csv` – PubMed abstracts table containing at least `PMID`, `Title`, and `Abstract` columns.

**Output**:
- `key_markers.csv` – one row per article containing markers, with columns:
  - `PMID`
  - `Title`
  - `Abstract`
  - `Markers` (comma-separated unique marker strings)
- Console output of the number of articles with extracted markers.

---

### 2. `Marker_count_base.py` – Marker-Count Threshold Baselines (Host / Receptor Binding / Virulence)

**Purpose**: Three parallel scripts evaluate how well a **single, fully interpretable feature – the total number of markers per strain (`Marker_Count`)** – can discriminate the target phenotype, using a thresholding strategy learned on the training+validation set. This provides a simple baseline to contextualize the full machine-learning models.

**Output** (per script, in its output directory):
- `*_Results.csv` – per-run results including the learned threshold, train+val metrics, and test metrics (ACC, Precision, Recall, F1, MCC, AUROC, AUPRC).
- `Summary_Mean.csv`, `Summary_STD.csv` – mean and standard deviation across runs.
- Console output of per-run thresholds, train+val and test metrics, and the number of successful/skipped runs.

---

### 3. `Algorithm_select.py` – Baseline Model Benchmarking

**Purpose**: Benchmarks 7 classical machine learning models using grouped data splitting. The best model is selected based on validation metrics.

**Models**: LR, SVM, KNN, GNB, RF, XGBoost, GBDT (default parameters, capable of multi-class or binary classification).

**Standardization**: Automatically applied for LR, SVM, KNN.

**Best model selection**:
- Host Prediction: highest validation AUROC
- Receptor Binding Preference: highest validation AUROC
- Virulence Prediction: highest validation AUROC

**Output**:
- `all_random_split_results_no_cv.csv` (or similar) – validation/test metrics per model per run.
- `summary_mean_*.csv`, `summary_std_*.csv` – aggregated statistics.
- Console output of the best model name.

---

### 4. `Feature_select.py` – Optimal Feature Number Search

**Purpose**: Ranks features by Random Forest Gini importance, then enumerates all possible feature subset sizes (1 to total features). Evaluates each subset on validation sets.

**Classifier used for evaluation**:
- Host Prediction: XGBoost (GPU accelerated: `tree_method='hist'`, `device='cuda'`)
- Receptor Binding Preference: SVM
- Virulence Prediction: XGBoost (default parameters)

**Procedure**:
- Same grouped data splitting as Script 3.
- For each run, train a Random Forest on the training set to obtain feature importance ranking.
- Iteratively take top‑k features (k = 1, 2, …, total features), train the classifier, compute validation metrics.
- Aggregate mean and standard deviation across runs.

**Output**:
- `All_TopN_Results.csv` – detailed metrics per run and TopN.
- `TopN_Mean_Results.csv`, `TopN_STD_Results.csv` – aggregated mean and standard deviation.
- Console output of the best TopN based on validation AUROC.

---

### 5. `Test.py` – Hyperparameter Tuning with Grid Search

**Purpose**: With a fixed number of features, performs hyperparameter grid search, selects the best parameters based on validation AUROC for each run, then evaluates the final model on the test set.

**Fixed number of features**:
- Host Prediction: 79
- Receptor Binding Preference: 26
- Virulence Prediction: 51

**Procedure**:
- Same grouped data splitting as Scripts 3 and 4.
- **Inner loop**: Select top‑N features (RF Gini importance) from the training set, standardize if needed, perform grid search over hyperparameters using validation AUROC.
- **Outer loop**: Re-select top‑N features from the combined training+validation set, train the final model with the best parameters found in the inner loop.
- Evaluate on the test set.
- For Host and Virulence: XGBoost with GPU acceleration (`tree_method='hist'`, `device='cuda'`).
- For Receptor Binding Preference: SVM.

**Output**:
- `all_runs_results.csv` – test metrics and best parameters per run.
- `test_summary.csv` – aggregated test metrics (mean ± std).
- Saved models (`joblib`) and selected feature lists (for Host Prediction project).
- Console output of best parameters and test set class distribution.

## How to Run

```bash
# Script 1 – Keyword-based mutation marker extraction
python extract_key_markers.py

# Script 2 – Marker-count threshold baselines (run the one matching your project)
python Marker_count_base.py

# Script 3 – Baseline model benchmarking
python Algorithm_select.py

# Script 4 – Optimal feature number search
python Feature_select.py

# Script 5 – Hyperparameter tuning and final test
python Test.py
```
